Generated by `experiments/rule_validation2.py` (seed 42). One row per sampled flow of the flow CSVs of CIC IoT-DIAD 2024. Per attack class and per rule (R1 external endpoint, R2 service port, R3 IP pair seen in Benign, any = R1|R2|R3) the sample holds 20 flows flagged by the rule and 20 flows kept by it (all flows if a stratum is smaller); a flow can serve several strata. All identifier columns and key features are in `audit_sample.csv` (same *ID*).

**Decision** (one word): `attack` = the flow is part of the attack of its folder label (sent by or to an attacking host as part of the attack, a scan probe, a flood packet train, a forged answer, or victim traffic relayed by a man-in-the-middle attacker); `background` = ordinary device, gateway or Internet traffic unrelated to the attack; `unclear` = cannot be decided from the evidence.

**Evidence** (short): what the decision rests on, e.g. "SSH from attacker .65 to victim .67 in attack window", "NTP to pool server, also in Benign", "pcap: frames via attacker MAC", "payload UNION SELECT". Useful checks: attacker/victim addresses and attack window in `captures/<capture>.json`, the packet release (pcap, `pcap_validation/<capture>/audit_sample_mac.csv`) where available.

Fill in ONE of `audit_template.md` / `audit_template_blind.md` (the blind one hides the rule flags and heuristic labels and is recommended, so that the decision does not anchor on the rule being validated). Do not change the ID column or the header row. Score after filling in:
`& $py experiments\rule_validation2.py --score-audit results_2026_03_03\q1_revision\rule_validation2\audit_template.md`

Heur. = heuristic label of rule_validation2 (S = signature flow, A = attack-related: attacker-victim flow, U = flow of an identified attacker with another peer (upper-bound definition only), - = none of these).
